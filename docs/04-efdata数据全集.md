# efdata 数据全集(东财 · efinance 封装)

> 2026-08-27 逐个实调 efinance 的 36 个对外接口得出,**不是抄 README**。
> 每行的「本机」列是当天在公司 Linux 上的真实调用结果;「列数」是真实返回的列。
> 工具:`$LAB/tools/efdata.py`(alias `efdata`)。

## 分工:什么用 astock,什么用 efdata

| 要什么 | 用哪个 | 为什么 |
|---|---|---|
| 实时行情 / 五档 / 逐笔 / 日线 | **`astock`** | 新浪 + 腾讯直连,本机稳定;东财的这几个接口在本机取不到 |
| 龙虎榜 / 股东户数 / 全市场业绩 / 可转债 / 基金 | **`efdata`** | 东财独有,别处没有 |
| 持仓业绩体检 + 估值分位 | **`hcheck`** | baostock 源,不依赖东财 |

**别拿 efdata 当行情工具。**它是补东财独有报表数据的,不是替代 astock。

## 本机可达性(2026-08-27 实测)

efinance 的 39 个导出函数里探了 36 个,**26 个通、10 个不通**。规律是**按接口路径分**,
不是按主机、也不是按协议:

| 主机 | 协议 | 本机 | 承载什么 |
|---|---|---|---|
| `datacenter-web.eastmoney.com` | **http** | 通 | 龙虎榜 / 股东户数 / IPO / 可转债全表 |
| `datacenter.eastmoney.com` | https | 通 | 报告期列表 |
| `emh5.eastmoney.com` | https | 通 | 前十大流通股东 |
| `hsmarketwg.eastmoney.com` | https | 通 | 实时快照 37 字段 |
| `fundmobapi.eastmoney.com` | https | 通 | 基金净值 / 持仓 / 行业 / 经理 |
| `fundztapi` + `search-codetable` | https | 通 | 指数成分股 |
| `push2.eastmoney.com` | 混合 | **部分** | `get_belong_board` 通;实时报价 / 逐笔 / 基本信息 不通 |
| `push2his.eastmoney.com` | 混合 | **不通** | K 线 / 分时 / 资金流日线 |

三条反直觉的事实,都实测过:

1. **协议不是判据。**`datacenter-web` 走的就是明文 `http://`,却一直稳定;
   `push2his` 走 `https://` 照样不通。强制把 efinance 里所有 `http://东财`
   改写成 `https://` 后重测,失败的仍然 0/3 —— 这条推断被自己的实测推翻了。
2. **主机也不是判据。**同一台 `push2` 上,`get_belong_board` 能通(35 行),
   `get_latest_quote` 不通。
3. **限流会随时间变化。**`get_history_bill` 首轮 10/10,连续请求后归零;
   `get_quote_history` 首轮 3/4,后来 0/10。所以 `efdata --check` 每次结果可能不同,
   标「不稳」的失败属预期,**不要重试硬刚**。

| `efdata holders <代码> [--periods N]` | 前十大流通股东 | 10 行 × 8 列 | 股票代码 / 更新日期 / 股东代码 / 股东名称 / 持股数 / 持股比例 / 增减 / 变动率 |

| `efdata dates` | 可用报告期列表 | 40 行 × 2 列 | 报告日期 / 季报名称 |
| `efdata board <代码>` | 所属板块与板块涨幅 | 35 行 × 5 列 | 股票名称 / 股票代码 / 板块代码 / 板块名称 / 板块涨幅 |
| `efdata members <指数代码>` | 指数成分股与权重 | 300 行 × 5 列 | 指数代码 / 指数名称 / 股票代码 / 股票名称 / 股票权重 |
| `efdata ipo` | 企业 IPO 审核状态 | 3259 行 × 9 列 | 发行人全称 / 审核状态 / 注册地 / 证监会行业 / 保荐机构 / 会计师事务所 / 更新日期 / 受理日期 / 拟上市地点 |
| `efdata survey <代码>` | **机构调研记录**（谁来调研、什么时候、什么方式） | 200 行 × 7 列 | 公告日 / 调研日 / 接待对象 / 地点 / 方式 / 参与人员 / 简称 |
| `efdata snapshot <代码>` | 实时快照 | 37 字段 | 代码 / 名称 / 时间 / 涨跌额 / 涨跌幅 / 最新价 / 昨收 / 今开 / 最高 / 最低 / 均价 / 涨停价 / 跌停价 / 换手率 / 成交量 / 成交额 / 买卖五档各价量 / 量比 / 委比 等 |

`snapshot` 与 `astock --l5` 数据重叠(都有五档),但字段更全(带涨跌停价、均价、委比)。

`survey` **不走 efinance,是直连东财 `RPT_ORG_SURVEYNEW`** —— akshare 的
`stock_jgdy_detail_em` 在本机报 TypeError(接口改版后封装没跟上),但底层接口是通的。
**「封装库坏了」不等于「数据拿不到」**,这是 2026-08-27 补搜时才发现的:
在此之前我把机构调研列进了「拿不到」那一档,实际上直连一下就有。
调研密度是**领先指标** —— 一天来 200 家机构和一个季度来 3 家,含义完全不同。

## 不稳档 · 6 个子命令(本机取不到,脚本会给替代方案)

| 子命令 | 拿什么 | 主机 | 替代 |
|---|---|---|---|
| `efdata kline <代码>` | K 线历史 | push2his | `astock <代码> --daily` |
| `efdata tick <代码>` | 当日逐笔 | push2 | `astock <代码> --tick` |
| `efdata info <代码>` | 基本信息(PE/PB/行业) | push2 | `hcheck <代码>:<成本价>` |
| `efdata spot` | 全市场实时行情 5000+ 行 | push2 | 单只用 `astock`;全市场无替代 |
| `efdata bill <代码>` | 历史每日主力资金流 | push2his | **本机无替代**,要用就在 另一台机器 跑 |
| `efdata billtoday <代码>` | 当日分钟级资金流 | push2 | **本机无替代**,要用就在 另一台机器 跑 |

失败时脚本退出码 `2`(区别于稳定档失败的 `1`),并打印替代方案。

## 通用参数

```
--head N       只显示前 N 行(默认 15)
--all          显示全部行
--csv 文件     存 CSV(utf-8-sig 编码,Excel 双击直接开,不乱码)
--check        探测各数据源当前可用性,不取数
--list         列出全部子命令
```

大表(`perf` 3885 行、`holdernum` 5553 行、`ipo` 3259 行、`cb` 1050 行)
**建议直接 `--csv`**,不要往终端打。

## efinance 里没包进来的 3 个接口

| 函数 | 为什么没包 |
|---|---|
| `fund.get_base_info` | 与 pandas 3.0.5 不兼容,抛 `TypeError: Invalid value '-0.11' for dtype 'str'`。这是 efinance 的库 bug,不是网络问题。需要的字段能从 `fundmgr` + `fundpct` 拼出来。 |
| `fund.get_pdf_reports` | 会往当前目录写 `pdf/<代码>/` 文件夹,副作用不适合放进速查工具。要用直接调 efinance。 |
| `futures.*` 四个函数 | 期货合约全表在本机返回 `JSONDecodeError`,且与 A 股分析这条线无关。 |

## 与 AI_Investment_Manager 的关系(别混淆)

`efdata` 是**数据层**工具:问一次答一次,无状态,不记得你持有什么。

`AI_Investment_Manager` 是**应用层**:70 个 API 路由里只有 5 个是数据查询,
其余是资产账本、交易流水、投资建议、打新全周期、OCR 导入持仓截图、备份。
它内部那 2287 行 `data_source.py` 是为自己的账本服务的,没有 CLI,
要跑起 FastAPI + 前端 + 数据库才能用 —— **不能当取数工具**。

完整对照见 `docs/A股分析仓选型对照.html`。
