# 01 · 环境与数据源

## Python 环境

```bash
bash install.sh          # 建 .venv、装依赖、把 skills 链进 ~/.claude/skills/
```

`install.sh` 在仓内建 `.venv`（Python 3.11），装：

```
akshare baostock pandas requests numpy pyarrow
```

可选：`edgartools`（只影响 `capex --engine both` 的交叉验证）、
`playwright`（只影响出 PDF）。

**不要用系统自带的 python3** —— macOS 自带 3.9 装 akshare 依赖会踩坑。
所有脚本都认 `$ASTOCK_VENV`，不设就用仓内 `.venv`。

## ★ 可达性按接口路径分，不按主机、不按协议

这是本仓最容易被想当然搞错的一件事，**同一个域名下不同路径的可达性可以完全相反**：

| 主机 | 路径 | 在受限网络下 |
|---|---|---|
| `eastmoney.com` | `datacenter-web`（龙虎榜 / 业绩 / 股东户数 / 机构调研） | ✅ 通 |
| `eastmoney.com` | `push2` / `push2his`（行情快照 / K 线） | ❌ 不通 |

所以「东财能不能用」这个问题**没有统一答案**，得问「东财的哪个接口」。
行情因此走新浪 + 腾讯，报表走东财 —— 不是因为东财整体不可用，是因为**它的行情接口不可用**。

同理，**换协议不解决问题**：把 `http://` 改成 `https://` 对可达性没有影响，
实测过（3 次请求全失败，与协议无关）。

### 两个会被误判成「不通」的坑

1. **新浪必须带 `Referer`**，否则 403。那是缺 header，不是不可达。
   工具和探针都已带 `Referer: finance.sina.com.cn`。
2. **404 / 403 说明主机是通的** —— 只是路径不对或缺 header。
   只有超时 / 连接失败（探针里显示 `不可达`）才是真的断。

## 你自己的情况：跑一次探针

数据源可达性**因网络环境而异**，别抄别人的结论：

```bash
$VENV/bin/python tools/probe_sources.py                 # 三张表全看
$VENV/bin/python tools/probe_sources.py --only blocked  # 只看拿不到的及原因与替代
$VENV/bin/python tools/probe_sources.py --md docs/07-数据源现状与缺口.md
```

`probe_sources.py` 里的 **WORKING / BLOCKED / REJECTED 三张表是权威** ——
它把「搜过、试过、验证过」的结论固化成可重跑的代码。
发现新的可用源或确认某个源失效，**改那三张表**，不要只写进文档：
文档不会被执行，代码会。

`docs/07` 是一份示例输出，让你在跑之前就知道输出长什么样。

## 代理

工具内部只对**自己这个进程** `os.environ.pop` 掉代理变量，**不动 shell 全局**：

```python
for _k in ("http_proxy", "https_proxy", "HTTP_PROXY", "HTTPS_PROXY",
           "all_proxy", "ALL_PROXY"):
    os.environ.pop(_k, None)
```

**为什么这么做**：国内数据源（新浪 / 腾讯 / 东财 / baostock）走代理绕出海反而取不到，
而同一台机器上别的命令又可能必须走代理。改全局会互相打架，
所以只在取数进程内去代理 —— 无代理环境下这是空操作，无副作用。

## 已知不用的源（省得你再踩一遍）

| 源 | 为什么不用 | 改用什么 |
|---|---|---|
| Yahoo Finance / yfinance | 直连 403、走代理 429 | 美股日线用 akshare `stock_us_daily`（新浪源） |
| stooq | JS 挑战页，脚本取不到 | 同上 |
| finviz | 403 挡爬虫 | — |
| financialmodelingprep | 401，付费 | — |
| mootdx（通达信） | TCP 握手通但取数返回空，库停更 | K 线用新浪 / 腾讯 |

完整清单（含**已知拿不到的数据及其原因、试过什么、替代是什么**）在
`probe_sources.py` 的 BLOCKED 表里 —— 那一节是它最有价值的部分，
省得你下次又从头搜一遍，或者误以为是接口坏了去修。
