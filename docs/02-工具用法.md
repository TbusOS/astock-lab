# 02 · 工具用法

13 个工具，除 `net_probe.sh` 外全部软链在 `stock-lab/tools/`，真身在 本仓 两个 skill 里
（`astock-quote` 管取数、`stock-analysis-workflow` 管方法）。

```bash
P=$VENV/bin/python                 # akshare / efinance 都在这个 venv
T=$LAB/tools
$P $T/<工具>.py ...
```

`~/.bashrc` 里已有 5 个别名：`astock` `hcheck` `efdata` `preport` `capex`。
其余 4 个可以照这个格式补：

```bash
for t in consensus:consensus journal:journal baserate:baserate probe:probe_sources; do
  echo "alias ${t%%:*}='$VENV/bin/python $LAB/tools/${t##*:}.py'"
done >> ~/.bashrc
```

## astock —— 行情速查

```bash
astock 300502            # 快照
astock 300502 --l5       # 附五档盘口
astock 300502 --tick     # 附逐笔成交（默认 20 笔，--tick=40 改笔数）
astock 300502 --daily    # 附最近日线
astock 300502 300308     # 多只
```

代码前缀自动判：`6`→sh、`0/3`→sz、`4/8`→bj。
数据源：快照/五档=新浪 `hq.sinajs.cn`；逐笔=腾讯；日线=新浪。

> ⚠️ **别拿 efdata 当行情工具。**东财的行情类接口（`push2` / `push2his`）在本机取不到，
> 但报表类接口（`datacenter-web`）是通的 —— **可达性按接口路径分，不按主机、不按协议**。
> 详见 `docs/01-环境与数据源.md`。

## hcheck —— 持仓业绩体检

```bash
hcheck 300502:400.00 300308:1100.00    # 代码:成本
hcheck 300502                            # 不带成本只体检
```

输出现价/浮亏、PE(TTM)、**PE/PB 估值分位（2020 至今）**、最新季报营收/净利同比、毛利率变化。
数据源：财务=akshare；估值分位=baostock；PE/市值=腾讯。

## efdata —— 东财报表数据

```bash
efdata --list            # 看全部子命令
efdata --check           # 探测当前哪些可用
efdata lhb               # 龙虎榜
efdata holdernum 300502  # 股东户数
efdata survey 300502     # 机构调研（akshare 封装已坏，走直连）
```

18 个稳定子命令 + 6 个本机取不到的（失败会打印替代方案，退出码 2）。
每个子命令拿到什么（含真实返回列）见 `04-efdata数据全集.md`。

## preport —— 八层决策报告 ★

```bash
preport 300502:400.00                 # 打屏
preport 300502:400.00 --md ~/r.md     # 存 markdown
preport 300502:400.00 --no-peers      # 跳过海外对照，快 20 秒
preport 300502:400.00 --no-baserate   # 跳过基准率（热缓存约 2 秒，冷缓存约 30 秒）
```

| 层 | 内容 | 源 |
|---|---|---|
| 1 | 持仓状况：成本 / 现价 / 浮亏 / 回本需涨幅 | 新浪 |
| 2 | 基本面：营收净利同比+环比、毛利率、ROE、EPS | efinance |
| 3 | 估值：PE/PB 历史分位 + 按业绩推的动态 PE 与 PEG | baostock + 腾讯 |
| 4 | 筹码杠杆：股东户数变化、融资余额、十大股东 | efinance + akshare |
| 5 | 风险：未来 10 个月解禁 | akshare |
| 6 | 技术位：均线、距高点回撤、**成本的历史分位** | akshare 前复权 |
| 7 | 海外同业：光模块上游链近 5 日 / 1 月 / 3 月涨跌 | akshare 美股 |
| **8** | **基准率：同类公司历史上保持住的比例（外部视角）** | **全市场季度业绩** |
| 9 | 判据小结：**每条判据后面自动挂上它的历史基准率** | — |

每层失败都降级不中断。

**第 7 层**是这个脚本存在的主要理由：A 股光模块 / 半导体的需求端在海外，
只看 A 股会漏掉「海外同行在涨而 A 股在跌」这类背离。

**第 8 层**解决另一个问题：前七层全是**这一家**的数据 = 内部视角，
人在内部视角下会系统性高估「这种好状态还能持续多久」。第 8 层换成外部视角，
第 9 层把数标进每条判据：

```
- 净利同比保持 **>50%**（当前 +91%）　—— 同类历史基准率 **24%**（起始 ≥ 90% 的公司里）
- 毛利率不掉 **3pp 以上**（当前 48.4%）　—— 同类历史基准率 **66%**
- 净利同比**跌破 30%** —— 历史上同类公司 4 个季度后**有 69% 会跌破这条线**
```

## capex —— 北美云厂 Capex（领先指标）★

```bash
capex --quarters 8 --md c.md      # 微软/谷歌/亚马逊/Meta 单季 Capex
capex --guidance                  # 他们自己给的下期指引（最领先）
capex --engine both               # 自写解析 vs edgartools 交叉验证
```

源：SEC EDGAR XBRL 官方，免费无 key，**UA 必须带联系方式**否则 403。
谷歌、Meta 的指引拿得到；微软、亚马逊在电话会口头给，不写进 8-K。

## consensus —— 券商一致预期（领先指标）★

```bash
consensus 300502              # 盈利预测 + 近 30 天评级变动
consensus 300502 --days 60    # 评级回看 60 天
```

源：同花顺（盈利预测，含机构数/最小/均值/最大）+ 巨潮（评级变化/前一次评级/目标价）。
**变动方向比绝对值有用** —— 连续下调是明确预警。

## baserate —— 基准率（外部视角）

```bash
baserate calibrate 300502                            # 给某只票直接校准（最常用）
baserate growth --threshold 90 --hold 50 --after 4   # 高增速的持续性
baserate margin --threshold 45 --drop 3 --after 4    # 高毛利的持续性
```

**平时不用单独跑 —— 它已经是 `preport` 的第 8 层。**
首次跑会拉 12 期全市场业绩（约 30 秒），之后走 `data/perf_cache/*.parquet`（约 2 秒）。

> ⚠️ **口径必须和判据是同一个问题。**「净利同比保持 >50%」是绝对线 → 用 `hold=50`；
> 「毛利率不掉 3pp 以上」是**相对自己**的线 → 用 `max_drop=3`。
> 混用会让基准率虚高 —— 实测毛利率那条差 **24 个百分点**（固定线 90% vs 相对口径 66%）。
> 改了判据或改了基准率，**跑 `check_baserate_wiring.py`**，退出码 0 才算过。

## journal —— 决策记录与复核（自我进化）

```bash
journal log 300502 --price 409.10 --action hold --falsify "..." --check 2026-10-31
journal review     # 到期待复核的
journal close 1 --principle "..."   # 复核后蒸馏成抽象原则
journal stats      # 命中率 + 概率校准 + 已蒸馏的原则
```

落盘在 `data/journal.jsonl` 与 `data/principles.jsonl`（不受 git 管）。

## probe_sources / check_sources.sh / net_probe.sh

```bash
probe_sources                  # 全部三张表
probe_sources --only blocked   # 只看拿不到的那些及原因与替代
probe_sources --md docs/07-数据源现状与缺口.md
```

`probe_sources` 是**权威**：它把「搜过、试过、验证过」的结论固化成可重跑的代码。
发现新的可用源或确认某个源失效，**改它的 WORKING / BLOCKED / REJECTED 三张表** ——
文档不会被执行，代码会。

## 用法建议

**季报后（尤其三季报 10 月底）跑一遍完整分析：**

```bash
journal stats                                # ⓪ 先读自己蒸馏过的原则
capex --guidance --md capex.md               # ① 需求源头 + 下期指引
consensus 300502 --md cons.md                # ①b 一致预期与评级变动方向
preport 300502:400.00 --md pos.md           # ②~⑤ 八层一次跑完（含基准率）
# 消息面（订单/砍单/产业进展）靠 WebSearch 补
journal log 300502 --price ... --action ... --falsify "..." --check <下个季报日>
```

分析方法本身（领先/滞后指标、预期差、赔率、基准率、自我进化）
在 skill `stock-analysis-workflow` —— 真身就在本仓 `skills/stock-analysis-workflow/SKILL.md`。
