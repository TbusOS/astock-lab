# extern-research-ingest —— 外部研报 → 结构化输入

## 为什么不写正则直接抽

各家投行版式完全不同(表头、单位、年度列、货币都不一样)。
正则在没见过的版式上**不是报错,而是抽出错的数** —— 抽错了不会有任何提示,比抽不到糟得多。

所以分工是:

| 谁 | 做什么 |
|---|---|
| 脚本 | 版面文本、表格候选、**逐页 PNG**、文件指纹、水印检测、待填模板 |
| 模型 | **看着渲染页**填 `filled.json` |
| `validate` | 用算术交叉核对,拦住转录错误 |

## 铁律:必须逐页看图

2026-09-01 踩过:高盛那份新易盛研报,最关键的三个数 ——
**12 个月前瞻 PE 的 `+1σ 40x / 均值 28x / −1σ 17x`** —— 只存在于 Exhibit 4 那张图里,
文本层一个都没有。只跑文本提取会得到一份**看起来完整、其实缺了估值锚**的输入。

而这三个数正是我们估值算错的原因:我们用 TTM PE 的历史分位(p50=44.9)去乘前瞻利润,
卖方用的是前瞻 PE 的历史带(均值 28x)。两者差 60%,单只票的 EV 差 45 个百分点。

同族参考:sky-skills 的 `tech-pdf-reader`,「图能看见才算读到」。

## 用法

```bash
# ① 机械抽取 + 逐页渲染 + 出待填模板
$VENV/bin/python tools/ingest_report.py extract <研报.pdf> --out private/extern_research

# 产物:
#   <slug>/meta.json     文件指纹 / PDF 元数据 / 是否加密 / 水印
#   <slug>/text.txt      按坐标重建的版面文本(列对齐,不依赖 poppler)
#   <slug>/tables.json   find_tables() 表格候选
#   <slug>/pages/pNN.png 逐页渲染
#   <slug>/filled.json   待填模板

# ② 用 Read 逐页看 pages/*.png,对着图和 text.txt 填 filled.json

# ③ 算术检查
$VENV/bin/python tools/ingest_report.py validate <slug>/filled.json
```

**顺序不能反。** 先填后看图,等于用文本层的残缺信息定了框,再看图也补不回来。

## 一批一起做

手上攒了一堆 PDF 时不要一份一份 `extract` —— 机械那一半可以成批做,
成批做完再看「还差谁没填」:

```bash
# ① 一次抽一批(目录递归找 *.pdf,也可以直接给若干路径)
$VENV/bin/python tools/ingest_report.py batch <放 pdf 的目录>
#   已抽过且**内容没变**的自动跳过(比 sha256,不比 mtime);--force 强制重抽
#   一份坏 PDF 不会让整批停下,失败的单独列出来
#   末尾自动打印待填清单

# ② 随时看还差哪几份
$VENV/bin/python tools/ingest_report.py pending

# ③ 逐份填完、validate 过了之后,出并排汇总
$VENV/bin/python tools/research_summary.py --out private/reports/<日期>/外部研报汇总.md \
    --holdings 300502.SZ:新易盛 300308.SZ:中际旭创 …
$VENV/bin/python tools/md2html.py <上面那个>.md <同名>.html "副标题" --no-disclaimer
node tools/html2pdf.mjs <同名>.html <同名>.pdf "页脚"
```

**为什么要有待填清单**:批量抽完之后,没人记得住哪几份填了、哪几份只填了一半。
不打这张清单,一批 PDF 抽进来就等于沉在目录里。

## 汇总:并排才有信息

一家投行的目标价单看没有意义 —— 它是一组假设的输出。有用的是**分歧**:
同一年同一家公司,A 给 EPS 22.99、B 给 18.85,差的那 22% 一定落在某条可以查的假设上
(出货量 / 单价 / 毛利率 / 费用率),不会凭空产生。

`research_summary.py` 出七节:

| 节 | 内容 | 为什么 |
|---|---|---|
| 1 覆盖 | 几份 / 几家 / 几只 / 报告日跨度 | **只有 1 份时明确说「无法给出分歧」** —— 那是数据缺,不是没有分歧 |
| 2 结论并排 | 评级 / 目标价 / 报告日股价 / 隐含空间 / 时效 | 隐含空间是**报告日**那天的,会过期,表里标出来 |
| **3 估值锚对照** | 方法 / 倍数 / 乘在哪一年 / 倍数依据 / 历史带 / 出处页 | **比目标价重要** —— 这是校准我们自己乘数的对照物 |
| 4 分年度分歧 | EPS / 净利 / 营收,行=年份 列=机构,带极差 | 极差大的那一年就是要去查的地方 |
| 5 逐份详情 | 修订方向 / 公司指引 / 风险 / 来源 / 利益冲突 | 有投行业务关系的,结论打折看,预测表照用 |
| 6 覆盖缺口 | 持仓里哪几只**一份外部研报都没有** | 没有外部对照的那几只,不确定性高一档,写报告时要标 |
| 7 怎么核对 | 每个数指回 filled.json / text.txt / pages/pNN.png / sha256 | 文档要能被检验,不是只能被相信 |

**单位不一致时拒绝并排,不做自动换算。** `Rmb mn` 和 `Rmb bn` 我能换,
`Rmb mn (adj.)` 和 `Rmb mn` 我换不了 —— 猜错的代价是一张看起来正常、
数字全错 1000 倍的表,而且没有任何一处会报错。所以单位不同就分开出表 + 标警告。

## `filled.json` 的结构

按「三情景要什么」倒推的,不是照抄研报目录:

| 节 | 装什么 | 为什么要 |
|---|---|---|
| `source` | 出处、日期、分析师、**provenance**、**利益冲突披露** | 转手流出的副本必须写清楚;投行与标的的业务关系会影响结论 |
| `call` | 评级、目标价、报告当日价、上涨空间、期限 | 期限尤其重要 —— 12 个月目标价不能和 2 年期情景混着加权 |
| **`valuation_anchor`** | 方法、倍数、**倍数的依据**、基准年、历史带 + **带的出处页** | **这是全篇最值钱的一节**。它是我们校准自己那套乘数的对照物 |
| `forecast` | 分年度 营收/净利/EPS/毛利率/净利率 | 三情景的输入 |
| `quarterly` | 分季度预测 | 一致预期只有年度,季度节奏只在研报里 |
| `revisions` | 本次上调/下调幅度 | **方向比绝对值有用**得多 |
| `company_guidance` | 公司自己给的指引 | 研报常引用,我们没有别的渠道拿到 |

## `validate` 的算术检查(10 条,每条都验过「故意填错就报」)

- 目标价 ÷ 报告当日价 − 1 ≠ 填的上涨空间 → 报错
- **目标价 ÷ 基准年 EPS ≠ 填的目标倍数** → 报错(最能抓转录错误的一条)
- 填了估值带却没填出处页 → 报错(这类数通常只在图里,必须能复核到页)
- `valuation_anchor.method` 空 → 报错
- `provenance` 空 → 报错
- 日期不是 `YYYY-MM-DD` → 报错
- `forecast` 为空 → 报错
- 各年「净利 ÷ EPS」推出的股本差异 > 15% → 报错(单位或转录错)
- **有 `forecast` 却没声明 `units`** → 报错。跨机构汇总时一家写百万一家写亿,
  数字并排全在合理区间,没有任何一处会报错 —— 这是最阴的一类错
- `conflict_disclosure` 空 → 警告

改动 validate 后,跑一遍探针确认每条还会响 —— **触发不了的检查是死代码**,
而且比没有检查更糟:它让人以为查过了。

## 水印:检测不到 ≠ 没有

脚本会扫文本层里的 `wechat:` 之类渠道痕迹,但**水印常是图片或旋转文字**,
文本层抓不到(高盛那份的「More reports @ wechat: Hillwood2024」就是)。
所以脚本在没检出时会明确提示「这不等于没有,看 pages/*.png 页边」。

## 边界:什么不该做

外资行研报是订阅制。**转手流出的副本不能建成自动管道** —— 不稳定,来源不合规。
正确姿势是把它当**外部输入**:人工放进 `private/extern_research/`,放多少用多少,
结构化后与自动取的数据**分开标注来源**。

需要持续、合规的海外信息,走 `data-sources` 那条路:云厂与海外同业的电话会纪要、
SEC 报表、前瞻一致预期 —— 研报里 90% 的信息量本来就来自这些。
