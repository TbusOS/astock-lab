# stock-analysis-workflow —— A 股个股分析工作流

## 一句话

**别把后视镜当挡风玻璃。**财报、股东户数、估值分位都是已经发生的事;
真正能提前看到拐点的只有四五个指标,先看它们,再用其余数据交叉验证。

## 0.5　先问它是哪个赛道(否则下面整套都可能用错)

**同一套判据套所有赛道会出错。**这一条 2026-08-28 被四只票同时打脸:

这套方法最早是围绕 **AI 算力链**长出来的,领先指标就一个 —— 北美云厂 Capex。
然后拿它跑**杰瑞股份(油气设服)**:

- 云厂 Capex 对它**完全无关**
- PEG 算出 **−15.30**(净利负增长)—— 这个指标在周期股上本来就没意义
- 净利增速的基准率也不适用(基准率库是全市场口径,对强周期股无效)
- 剩下能用的只有滞后的财报与估值分位

**结论不是「工具坏了」,是「用错了框架」。**

| | 成长股 | 周期股 |
|---|---|---|
| 看什么 | 增速**持续性** | **周期位置** |
| PEG | 有意义 | 盈利低谷给「便宜」假信号、高峰给「贵」假信号 |
| 高 PE | 通常是贵 | 常常是**盈利低谷**(该买) |
| 低 PE | 通常是便宜 | 常常是**盈利高峰**(该卖) |
| 基准率 | 适用 | 不适用(全市场口径对强周期无效) |

```bash
sectors                # 看已定义的赛道
sectors 002353         # 判某只票属于哪个赛道、该用什么领先指标与判据
```

`sectors.py` 给出四件事:**① 领先指标是什么 ② 从哪取 ③ 判据模板
④ 哪些常用指标在这个赛道会给出假信号**。

### 两个判赛道的坑(都踩过)

1. **不能把板块名拼成一个串再匹配** —— 会制造跨边界的假命中。
2. **不能先命中先用** —— 一只票能挂 34 个板块,大量是**概念板块**。
   杰瑞股份主业是油服,却也挂着「液冷服务器」「动力电池回收」「核能核电」。
   只看第一个命中的,就把油服票判成了 AI 算力链。
   现在按**命中数量打分**,前 3 个板块权重 ×3(那通常是行业分类,后面是概念标签),
   并且**把次选赛道也报出来** —— 主判可能错,读者要能一眼看到它还沾着别的赛道。

> ⚠ `sectors.py` 里标 **❌** 的是**工具缺口不是「数据拿不到」** —— 是还没做。
> 油价、全球油气资本开支、北美钻机数(Baker Hughes,每周免费公布)都还没接。
> 所以对油服票,这套工具目前给出的结论**证据强度低于 AI 算力链的票**,
> 报告和 journal 里都要写明这一点。

## 1　领先 / 同步 / 滞后:先分清再看

**这是本 skill 最重要的一张表。**分析顺序必须按这个来,不能反过来。

⚠ **下面这张表是 AI 算力链的。**别的赛道先跑 `sectors <代码>` 拿它自己的那张。

### 领先指标(看未来 —— 先看这些)

| 指标 | 领先多久 | 怎么取 | 现状 |
|---|---|---|---|
| **北美云厂 Capex 同比** | 领先 A 股算力链业绩 **1–2 个季度** | `capex` | ✅ 可用(SEC EDGAR 官方) |
| **海外同业股价** | 市场对同一需求先反应,常领先 A 股数周 | `preport` 第 7 层 | ✅ 可用 |
| 云厂**下季度 Capex 指引** | 再领先 Capex 一个季度 | **8-K 的 EX-99.1 新闻稿** | ✅ 可用 `capex --guidance`(谷歌/Meta 拿得到;微软/亚马逊在电话会口头给,拿不到) |
| 券商一致预期**变动方向** | 连续下调是明确预警 | 同花顺 + 巨潮 | ✅ 可用 `consensus`(19 家机构预测 + 评级变动) |
| 在手订单 / 产能规划 | 领先收入 1–3 季 | 公告 / 调研纪要 | ⚠️ 手工(巨潮 PDF) |
| 产业高频数据(出货量/报价) | 最领先 | LightCounting 等付费库 | ❌ 拿不到 |

**判据:领先指标转向 → 立刻重新评估,不等财报确认。**

### 同步指标(看现在)

股价与均线 · 融资余额 · 龙虎榜 · 北向成交占比 · 大宗交易折溢率。
这些反映当下的资金行为,**不预示方向,但能解释「为什么现在这个价」**。

### 滞后指标(看过去 —— 最后看,只用来验证)

| 指标 | 滞后多久 |
|---|---|
| 财报(营收/净利/毛利率) | 1–2 个月 |
| 股东户数 | 约 2 个月 |
| 前十大流通股东 | 最长 5 个月 |
| PE/PB 历史分位 | 基于已发生的盈利 |

**滞后指标的正确用法:不是用来判断买卖,是用来验证领先指标给出的故事成不成立。**

> **反面教材**:只看「净利 +91% 所以该买」——那是上半年已经发生的事,
> 股价早已反应过。真正要问的是「下半年还能不能保持」,那要看 Capex 和订单。

## 1.5　前瞻性思维:投资投的是未来(本 skill 的核心)

> **先破一个误解:顶尖投资者并不预测价格。**
> 他们做三件事 —— 找预期差、看变化率、算赔率。这三件都是前瞻的,而且都可验证。
> 只会复述「净利 +91% 所以好」的分析,是把后视镜当挡风玻璃。

### ① 预期差:市场已经 price in 了什么?我知道什么它不知道

**这是全部前瞻性的起点。**股价 = 市场对未来的共识。你要赚的钱来自
**共识错了而你对**,不是来自「公司好」——公司好早在价格里了。

三问,必须按顺序答:

| 问 | 怎么答(可操作) |
|---|---|
| **市场现在 price in 了什么?** | 用当前市值反推隐含预期:`市值 ÷ 合理 PE = 市场隐含的净利`。再对比券商预测和你自己的推算,差在哪 |
| **市场在担心什么?** | 从暴跌日的新闻、券商下调理由、龙虎榜解读里找。担忧要具体到「哪个变量会变坏」 |
| **这些担忧哪些已被证否?** | **这一步是前瞻性的来源。**用领先指标去证伪:Capex 数据、海外同业、订单公告 |

> **已被证否的担忧 = 你的预期差。**市场还在为一个不成立的故事定价,
> 而你有官方数据证明它不成立 —— 这才是可下注的判断,不是「我觉得会涨」。

### ② 变化率:看二阶导,不看水平值

**「好」不赚钱,「变得更好」才赚钱;「差」不亏钱,「变得更差」才亏钱。**

| 只看水平(错) | 看变化率(对) |
|---|---|
| 净利率 30%,很高 | 净利率从 25% → 30%,还在升 |
| Capex 165B,很大 | Capex 同比 +65% → +87%,**增速在加速** |
| PE 43x,不便宜 | PE 分位 44%,且分母(盈利)增速 91% |

**拐点判据:同比增速的二阶导转负 = 顶部信号,比绝对额下降早 1–2 个季度。**
例:Capex 绝对额还在涨但同比从 +87% 掉到 +40%,那时就该减仓,不等它掉到负。

### ③ 赔率 × 概率:不问「会不会涨」,问「赢面多大、赔赚多少」

**下注框架**(每次给建议都要算):

```
下行空间 = 现价 → 最坏情形价位(前低 / 悲观估值)
上行空间 = 现价 → 合理情形价位(中性预测 × 合理 PE)
赔率     = 上行 ÷ 下行
```

- **赔率 < 2:1 → 不值得下注**,哪怕你觉得会涨
- **赔率 > 3:1 且领先指标向上 → 值得持有甚至加仓**
- 概率不用精确,分三档就够:领先指标全向上=高;分歧=中;向下=低

### ③b 基准率:用外部视角压住过度乐观(Mauboussin)

**「净利同比 +91%」听起来很强,但没有参照系。**人做判断时用的是**内部视角** ——
盯着这家公司的故事,系统性高估它能持续多久。
**基准率是外部视角**:历史上处在同样位置的公司,后来怎么样了。

`baserate` 用全市场季度业绩(每期 4200-5600 家)算,零成本零 key:

```bash
baserate calibrate 300502                            # 给某只票直接校准(最常用)
baserate growth --threshold 90 --hold 50 --after 4   # 高增速的持续性
baserate margin --threshold 45 --drop 3 --after 4    # 高毛利的持续性
```

**不用单独跑 —— 它已经是 `preport` 的第 8 层。**报告第 9 层的每条判据后面
会自动挂上对应的基准率,不必自己记「24% 是哪个问题的答案」。

**2026-08-27 全市场实测(12 个报告期 2023-09-30 ~ 2026-06-30):**

| 起始条件 | 之后 | 基准率 |
|---|---|---|
| 净利同比 ≥ 90% | 4 个季度后仍 ≥ 50% | **24%**(区间 19%~28%,8 段) |
| 净利同比 ≥ 90% | 4 个季度后仍 ≥ 30% | 31%(25%~37%) |
| 净利同比 ≥ 90% | **2 个季度**后仍 ≥ 50% | 47%(32%~70%) |
| 毛利率 ≥ 45% | 4 个季度后**相对自身**下滑 ≤ 3pp | **66%**(60%~72%) |
| 毛利率 ≥ 45% | 4 个季度后**相对自身**下滑 ≤ 5pp | 77%(71%~82%) |

**读法:**
- **高增速的均值回归比直觉强得多** —— 四个季度后只有约四分之一还能维持,
  两个季度后也才不到一半。这正是「高估值往往先于低于平均的回报」的机制。
- **毛利率的粘性高于增速**(77% vs 24%),但没有高到可以忽略。
  含义是**利润增速先掉、毛利率后掉** —— 所以「毛利率还没动」不能当成
  「增速能撑住」的证据,它本来就是更慢的那个指标。

### ⚠ 基准率的口径必须和判据是同一个问题

这一条 2026-08-27 真踩过,是这一节最容易出错的地方。

判据「毛利率不掉 3pp 以上」是**相对自己**的线。如果基准率按**固定线**算
(「起始 ≥45% 的公司,4 期后仍 ≥42%」),一家起始 48.4% 掉到 43% 的公司
**违反了判据**(它该 ≥45.4%),却仍算进固定线的分子。

实测这个口径差:**固定线 90% vs 相对口径 66%,虚高 24 个百分点。**
报告里印出来是「毛利率不掉 3pp　—— 历史基准率 90%」,那个 90% 回答的是
一个更容易的问题,而读者从字面上完全看不出来。

- **判据是绝对线**(「净利同比保持 >50%」)→ 用 `rate(..., hold=50)`
- **判据是相对线**(「不掉 3pp 以上」)→ 用 `rate(..., max_drop=3)`
- 这条约束有可执行闸:`check_baserate_wiring.py`,**改判据或改基准率后必须跑**

**怎么接到期望值框架:基准率直接约束 bull 情景的概率。**
如果历史基准率是 24%,你却想给 bull 35%,**必须说出这家公司凭什么超出基准率** ——
已锁定的长约订单、独家产能、客户结构,而不是「行业景气」这种谁都能说的话。

> ⚠️ 基准率是**下限约束不是预测**。它告诉你「凭什么」这个问题该多难回答,
> 不告诉你这一家会怎样。

### ④ 安全边际:先问「错了会怎样」

**永远先算下行。**具体做法:
- 假设你的核心判断(如「1.6T 会放量」)**是错的**,业绩只做到市场悲观预期
- 用悲观净利 × 历史 PE 下四分位 → 得到最坏情形市值 → 换算价位
- 那个价位到现价的距离,就是你要承受的
- **如果那个跌幅你受不了,仓位就是重了**,与看不看好无关

### ⑤ 反身性:价格本身会影响基本面

高位增发容易、员工期权值钱、客户更愿意下单;暴跌则相反。
**筹码分散(股东户数暴增)+ 杠杆高 = 下跌会自我强化**,这不是纯情绪,
它会真实影响公司融资和扩产节奏。所以筹码数据虽然滞后,仍要看。

### 落到报告里:结论段必须这么写

**不合格**(纯描述历史):
> 净利同比 +91%,毛利率 48.4%,估值 PE 43x 处于历史 44% 分位,建议持有。

**合格**(前瞻 + 可证伪):
> 市场在为「AI 资本开支见顶」定价,当前市值隐含 2026 净利约 150 亿(动态 PE 38x)。
> **但这个担忧已被 SEC 官方数据证否**:四大云厂 Capex 同比从 +65% 加速到 +87%。
> 预期差在这里。赔率:下行到前低 347(−15%),上行到中性预测 645(+58%),约 1:3.9。
> **判据**:若下季度 Capex 同比掉到 +20% 以下,预期差消失,立即清仓。

**每条结论都要能被未来的数据证伪。**不能证伪的话不要写。

## 1.6　自我进化:让这套方法真的越用越准

### 三样东西缺一不可

| 记什么 | 落在哪 | 不记的后果 |
|---|---|---|
| **决策** —— 当时判了什么、可证伪判据是什么 | `journal log` → `data/journal.jsonl` | 复核时不知道自己当初赌的是什么 |
| **证据** —— 当时看到的每个数字 | `preport` 自动落 `data/snapshots/<代码>/<日期>.json` | 复核时说不清「是数据变了还是我看错了」 |
| **变化** —— 这次 vs 上次逐项对比 | `preport` 第 0 节(自动) | 判据悄悄接近触发而你没察觉 |
| **当时的推理** —— thesis 与可证伪判据 | 快照里的 `reasoning` 段(自动从 journal 取) | **分不清「推理错了」还是「世界变了」** |

最后一条最容易漏。**只存数字的话,下次回来只能看到「净利同比掉了 19pp」,
看不到「我上次凭什么认为这不要紧」。**而这两种情况的改进方向完全相反:

- **推理错了** → 要改方法(那正是自我进化要改的东西)
- **世界变了而推理没问题** → 只要更新事实,方法不用动

分不开就没法进化。所以快照里同时存事实和当时的 thesis / falsify / 概率假设,
下一轮 `preport` 会把它读回来印在第 0 节后面。

### 一份数据,两种呈现

| 给谁 | 是什么 | 怎么产生 |
|---|---|---|
| **AI** | `data/principles.jsonl` + 每份快照里的 `reasoning` 段 | 结构化,下一轮分析直接读回去 |
| **人** | `journal stats --html <文件>` | 原则库 + 待复核 + 决策时间线 + 概率校准 |

**不是两份数据,是同一份的两种呈现。**AI 要的是能直接吃进去的结构;
人要看的是**知识库怎么长出来的** —— 哪条原则从哪次教训里来、
当时的判断是什么、后来对不对、概率估偏了多少。

```bash
journal stats                      # 终端看
journal stats --html kb.html       # 出给人看的视图
```

空知识库时它也说得清楚:还有多少天到最早的复核日、下一次能蒸馏原则的机会在哪。

**为什么证据要单独落一份 JSON,而不是留着 markdown 报告去翻:**
两份 markdown 做 diff 得到的是排版噪音。要比的是**结构化的数**——
净利同比从 +110% 掉到 +91%(−19pp)、毛利率 50.6% → 48.4%(−2.2pp,判据线 47.6%)。
这种对比只有结构化数据能自动做。

第 0 节长这样:

```
| 指标 | 上次 | 这次 | 变化 |
| 净利同比 | 110.0% | 91.0% | ▼ 19.0pp |
| 毛利率 | 50.6% | 48.4% | ▼ 2.2pp |
| 股东户数 | 155,489户 | 257,067户 | ▲ 101,578户 |
🔴 变差 7 项  ✅ 变好 3 项
```

**读法不是看涨跌,是看「上次的判据现在离触发有多远」。**
判据接近触发而你没动作,那就是该记进 journal 的东西。



> **这是原先最大的漏洞。**流程是单向的 —— 分析 → 给建议 → 结束,
> 没有任何机制记录「当时判断了什么、后来对不对、错在哪」。**不复核就不会进步。**

### 借 EvolveR 的三阶段循环

参考 EvolveR(arXiv:2510.16079,见 `ai-doc/self-improving-agents/evolver.md`),
落到投资分析上:

| EvolveR 阶段 | 在这里对应什么 | 工具 |
|---|---|---|
| **① 在线交互** | 每次分析产生一条轨迹:结论 + 三情景概率 + **可证伪判据** | `journal log` |
| **② 离线自蒸馏** | 到期复核,把「对了/错了」压缩成**抽象原则** | `journal close --principle` |
| **③ 策略进化** | 下次分析**前先读**这些原则,修正自己的先验 | `journal stats` |

**EvolveR 的关键发现:3B 规模下,自蒸馏的原则优于更大教师模型的指导。**
自己的经验比外部知识管用 —— 前提是你真的记录并复核了。

### 蒸馏出的必须是抽象原则,不是流水账

| ❌ 流水账(没用) | ✅ 抽象原则(有用) |
|---|---|
| 「300502 那次判断对了」 | 「有明确领先指标支撑时,我倾向**低估 bull 概率**」 |
| 「8 月买错了」 | 「成本落在历史 <20% 分位的窄带时,我总在反弹初期就想补仓」 |
| 「Capex 数据很有用」 | 「只用网页搜的单一预测会算错 EV —— 必须用一致预期的分布」 |

原则要能**指导下一次不同的判断**,不能只描述这一次。

### 概率校准是这个循环最值钱的产出

`journal stats` 会把「当时 EV 预期」和「实际涨跌」并排列出来算偏差:

- 平均比预期**低 5pp 以上** → 你系统性过度乐观,下次调低 bull 概率
- 平均比预期**高 5pp 以上** → 偏保守,可以适度提高 bull 概率

**三五次复核之后就能看出自己在哪类判断上系统性偏差。**
这是任何外部研报都给不了的东西。

### 反面教材:设计不等于实现

自我进化这一层特别容易停在设计上 —— 蓝图画得很完整(原则库、成功计数、
自动蒸馏),文件建好了,然后**一次没跑过,至今 0 字节**。
2026-08-27 精读一个同类项目时实测到的就是这个:四层架构里有两层零代码,
自进化文件全空。

**判断一个自进化设计有没有真跑,只看一件事:它的原则库里有没有东西。**
所以这里给的是最小可用实现 —— 一个 JSONL + 四条子命令,人和 AI 都能直接读,
跑不跑得起来一眼可见。

### 硬规矩

**每次给出投资结论,必须同时 `journal log` 一笔,且必须写 `--falsify`。**
不能证伪的结论不值得记,也不值得给。

## 2　五层分析顺序

按这个顺序做,每层给一个结论再进下一层。

```
① 需求源头   云厂 Capex 同比在加速还是减速？        capex
     ↓        决定这条链未来 1-2 季有没有量
② 同业对照   海外同行涨还是跌？与本股背离多少？      preport 第 7 层
     ↓        背离 >15pp 说明跌的是情绪不是需求
③ 公司质地   营收净利同比+环比、毛利率、现金流       preport 第 2 层
     ↓        验证前两层的故事在公司层面成不成立
④ 估值位置   PE/PB 历史分位 + 动态 PE + PEG          preport 第 3 层
     ↓        决定「对不对」之外的「贵不贵」
⑤ 筹码情绪   股东户数、融资余额、龙虎榜、北向占比    preport 第 4 层 + efdata
              决定「短期会不会继续跌」,不决定长期
```

**层级不能跳。**先看 ⑤ 再看 ①,就会被短期波动带着走。

## 4　判据模板(照抄,把数字换掉)

分析结论必须落成**可执行的判据**,不能停在「看好/看空」。

### 继续持有的前提(下个季报逐条核)

- 净利同比保持 **> 某阈值**(通常取当前值的 1/3)
- 毛利率不掉 **3pp 以上**
- 营收环比不转负
- **领先指标(Capex 同比)不掉档**

### 减仓 / 清仓触发

| 触发 | 含义 | 动作 |
|---|---|---|
| 净利同比跌破 30% | 增速掉档 | 减仓一半 |
| 毛利率掉 5pp | 价格战开打 | 减仓一半 |
| **云厂 Capex 同比跌破 +20%** | **需求源头转向** | **清仓** |
| PE 历史分位回到 80%+ | 估值透支 | 分批兑现 |
| 海外同业转跌而本股独强 | 需求端预警 | 减仓 |
| 股东户数继续大增**且**股价创新高 | 还在派发 | 不追高 |

### 补仓区间的定法

跑 `preport` 看「**成本在历史中的位置**」:若成本落在过去一年只有 <20% 交易日
站得住的窄带,说明买点接近阶段顶部 —— **不在当前价补,等回到前一个明确低点附近**,
且分 3 批、每批不超过原仓位 1/3。

## 5　报告结构(结论前置)

**人们最想知道的是「接下来怎么做」,不是「数据是什么」。**

```
封面     现价 / 成本 / 浮亏 / 回本需涨   四个 KPI
结论     一句话:持有还是卖,为什么
1 三档操作   现在做什么 · 什么价补 · 什么时候卖(判据表)
2 证据      领先指标优先:Capex → 同业 → 龙虎榜 → 北向
3 风险      变差的部分(筹码/杠杆),不藏着
4 基本面与估值   滞后指标,放后面当验证
5 技术位
6 数据完备性    诚实说缺什么、影响多大
```

出 PDF:写 HTML(用 skill `anthropic-design` 的 CSS)→ playwright 转 PDF。
**不要用 md2pdf** —— 它不支持行内粗体和颜色,出来是纯黑白。

```bash
# HTML → PDF(在 sky-skills 目录跑,那里有 playwright)
cd ~/claude-tools/sky-skills && node <<'EOF'

const b = await chromium.launch(); const p = await b.newPage();
await p.goto('file://' + path.resolve(process.argv[2]), {waitUntil:'networkidle'});
await p.emulateMedia({media:'print'});
await p.pdf({path:process.argv[3], format:'A4', printBackground:true,
  margin:{top:'12mm',bottom:'12mm',left:'10mm',right:'10mm'}});
await b.close();
EOF
```

### 北向数据的特殊情况(容易误判成「接口坏了」)

- **2024-05-13** 起停止披露北向**日内实时**进出金额
- **2024-08-19** 起停止披露**日终**数据,改为**按季公布**
- akshare 的日度北向持股接口数据停在 **2024-08-16**,这不是 bug

**替代口径(仍每日公布,已验证可用)**:深股通/沪股通**前十大成交活跃股**。
东财 `RPT_MUTUAL_TOP10DEAL`,`MUTUAL_TYPE` 取值 `001`=沪股通、`003`=深股通、`002`=港股通。
字段里 `DEAL_AMT`(北向成交额)、`MUTUAL_RATIO`(占该股总成交比例)有值,
**`NET_BUY_AMT` 为 None**(净买额不再披露)。

> 拿得到「参与度」,拿不到「方向」。判读方式:占比持续抬升 = 北向参与加深;
> 但涨是买跌是卖无法区分,要配合股价走势一起看。

## 7　常见误判(都踩过)

| 误判 | 真相 |
|---|---|
| 「净利 +91% 所以该买」 | 那是**上半年已发生**的事,股价早反应过。要问下半年 |
| 「东财被墙了」 | 按**接口路径**分,不是整体被墙;报表类一直可用 |
| 「改 http 为 https 能提高成功率」 | 实测推翻:`datacenter-web` 走明文 http 却最稳 |
| 「北向数据接口坏了」 | 是监管改了披露规则,换十大活跃股口径 |
| 「edgartools 的 fiscal_period 可信」 | 它把谷歌 180 天累计标成 Q2,**偏高 76%**,必须自己差分 |
| 「券商目标价可以当依据」 | 只作参考。**变动方向比绝对值有用** |
| 「跌了就是基本面坏了」 | 先看 Capex 和海外同业;背离 >15pp 说明是情绪 |

## 8　这套方法的边界

**支持**:以季度为单位的持有 / 减仓决策。四个维度硬数据 + 多条独立证据互证。

**不支持**:择时和波段。缺产业高频数据(出货量/报价)和一致预期跟踪,
而这两块恰好决定短期资金流向,且都不在免费数据源里。

**永远不做**:承诺价格。所有结论都是「在什么条件下该做什么」,不是「会涨到多少」。
